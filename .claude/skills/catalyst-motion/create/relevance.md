# Relevance — draw the real thing

Freshness keeps films from repeating themselves. Relevance keeps them **about the product**. A hero object
that is new but generic, like stacked rhombus slabs standing in for "a Stratus bucket", fails both the viewer and the brief.

## 1. The 2-second test (gate, every scene)
Show the frame **without any labels** to someone who works in the product's category. Within ~2 seconds they
should name the hero object correctly: "a bucket of files", "a database table", "a browser deploying",
"an API request". If they'd say "a box", "layers" or "a cube", the object is wrong. **Labels don't count**: a box
labelled `AUTH` is still a box.

## 2. Vocabulary map — recognisable objects per Catalyst service
Draw these as iso objects, within the DNA (dark faces, gradient edges, light is the only colour).

| Service | Hero objects people recognise | Light / motion that reads as the service |
|---|---|---|
| **Stratus** (object storage) | **A bucket**: open-top pail or tub, rim and handle optional, files visibly inside. **Objects**: file icons with type glyphs (img, mp4, pdf, csv), thumbnails, folders. **Keys/paths** (`media/hero.png`). Upload/download arrows. | Files dropping into and lifting out of the bucket; a path string resolving to a file; downloads leaving freely |
| **Slate** (frontend hosting) | Browser windows, a live site preview, a URL bar, a globe or region map for the edge, framework logos as wordmarks | A page rendering in, a URL going live, requests reaching edge points |
| **AppSail** (PaaS) | App windows, running-instance tiles with status, container images (layered *with* a whale-free generic container shape), a server rack for migration | Instances appearing and retiring; a deploy turning an app on |
| **CloudScale** (BaaS) | Database tables with rows, a login screen or lock for auth, API endpoint cards (`POST /bookings`), an envelope for mail, a phone with a push | A request travelling client → endpoint → table row → notification |
| **Signals** (events) | Event cards or messages, a bus line with subscribers, bells | An event fanning out to subscribers |
| **QuickML / Zia** (AI/ML) | A model card, a dataset table, a prediction chart, a sparkle mark for the agent | Data → a model → a prediction appearing |
| **Functions / Circuits** | Code blocks `{ }`, a function card with input → output, flow nodes | Input in, result out; steps lighting in order |
| **Agents (any)** | One recognisable agent mark (a sparkle) next to the real UI it operates | The action appearing in the product UI |

**When a service needs a new object,** add it here with the same two columns.

## 3. Banned generic stand-ins (as heroes)
These can never carry a scene's meaning on their own:
- **Stacked rhombus slabs / layered flat squares** ("strata", "layers", "lattice rings"). Retired in the ledger.
- Plain cubes or boxes standing in for a service ("a box = auth", "a box = a function").
- Platforms or tile floors as "the cloud".
- Cylinders as "the database" unless they also show rows or a table.
- Abstract rings, orbits or portals **with nothing recognisable passing through them**.

A metaphor is allowed **only if a literal anchor shares the frame.** The Stratus "0" portal worked because files
flowed through it. A ring of badges works because the badges read as compliance seals.

## 4. Brief line (add to the freshness block)
```
Relevance (2-second test) : scene → hero object → what a viewer would name it   (no labels)
```
